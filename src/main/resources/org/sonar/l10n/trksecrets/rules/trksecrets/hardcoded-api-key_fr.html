Les clés d'API et les jetons d'accès donnent accès à un service au nom de leur propriétaire. Une fois versionnés, ils doivent être considérés comme compromis.

Pourquoi est-ce un problème ?

Un identifiant ne doit jamais apparaître en clair dans le code source : utilisez un coffre de secrets (comme Vault ou credstash) et référencez les secrets par leur identifiant.

Exemple de code non conforme

api_key: "k8Jd92LmQp0xZvB3nTa7"

Solution conforme

api_key: ${API_KEY}

Remarques

Détectée à partir des noms de clé se terminant par key ou token, avec une valeur d'au moins 16 caractères sans espace qui ne ressemble pas au nom de la clé.
