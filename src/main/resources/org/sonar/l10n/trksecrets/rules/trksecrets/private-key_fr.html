Une clé privée versionnée dans un dépôt doit être considérée comme compromise, même si elle est supprimée ensuite : elle reste dans l'historique.

Pourquoi est-ce un problème ?

Un identifiant ne doit jamais apparaître en clair dans le code source : utilisez un coffre de secrets (comme Vault ou credstash) et référencez les secrets par leur identifiant.

Exemple de code non conforme

-----BEGIN RSA PRIVATE KEY-----

Solution conforme

Stockez la clé dans un coffre ou un magasin de clés et référencez-la par son identifiant.

Remarques

Inactive par défaut : sonar-text couvre déjà les clés privées dans SonarQube.
