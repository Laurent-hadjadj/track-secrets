Signale les correspondances des règles définies dans le fichier configuré par track.secrets.customRules.path, sans recompiler le plugin.

Pourquoi est-ce un problème ?

Un identifiant ne doit jamais apparaître en clair dans le code source : utilisez un coffre de secrets (comme Vault ou credstash) et référencez les secrets par leur identifiant.

Exemple de code non conforme

rule.my-token.value=^MT[A-Z0-9]{30}$

Solution conforme

Voir la documentation du fichier de règles personnalisées.

Remarques

Active par défaut, elle ne signale rien tant qu'aucun fichier de règles personnalisées n'est configuré.
