Un mot de passe écrit en clair dans le code source ou dans un fichier de configuration est lisible par toute personne qui a accès au dépôt, à son historique, aux artefacts de construction ou aux journaux. Il ne peut pas être renouvelé sans nouvelle livraison.

Pourquoi est-ce un problème ?

Un identifiant ne doit jamais apparaître en clair dans le code source : utilisez un coffre de secrets (comme Vault ou credstash) et référencez les secrets par leur identifiant.

Exemple de code non conforme

db.password=Sup3rS3cret!

Solution conforme

db.password=${DB_PASSWORD}

Remarques

Détectée à partir du nom de la clé (password, passwd, pwd, pass). Les valeurs contenant plus d'un espace (libellés), les espaces réservés et les variables sont ignorés. Dans les fichiers Java, Kotlin, C#, Python, JavaScript, TypeScript et PHP, la règle est ignorée par défaut (propriété track.secrets.skipNativeOverlap) car les analyseurs de ces langages fournissent déjà S2068.
