Reports the matches of the rules defined in the file configured by track.secrets.customRules.path, without rebuilding the plugin.

Why is this an issue?

Credentials must never appear in clear text in source code: use a credentials store (such as Vault or credstash) and refer to secrets by identifier.

Noncompliant code example

rule.my-token.value=^MT[A-Z0-9]{30}$

Compliant solution

See the documentation of the custom rules file.

Notes

Active by default, it reports nothing unless a custom rules file is configured.
